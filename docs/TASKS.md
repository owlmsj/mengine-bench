# Tasks

One row per task, generated from the catalog (`uv run mengine-bench tasks-doc
--write`); a test fails when this table drifts from the code. Weight 2 marks
HARD/long-horizon tasks.

FAST already contains all four weight-2 tasks. FULL adds two weight-1 tasks.

## Par times

The catalog has 12 measured par times and two derived par times (see
[SCORING.md](SCORING.md#par-times)). Measured values come from the maintainers'
DeepSeek V4.1 Flash runs of the private v1 suite:

- 2026-09-23 FAST run: `ds-ab-playtest`, `bo-pnl-runway`, `cmp-handoff`,
  `lc-changelog`, `vis-chart`, `gd-astar-doors`, `gd-ecs-collision-bug`,
  `ds-sql-funnel`, `ir-studio-wiki`.
  Published values are rounded up to whole seconds, except `ir-studio-wiki`
  which retains its measured 14.6 s.
- 2026-09-24 one-shot runs: `gd-integration-repo` (89 s),
  `web-mondrian-landing` (345 s), `3d-voxel-landscape` (295 s).

The two FULL-only tasks had no measured reference run. Their pars are twice
the closest measured task's time, rounded up to whole seconds for backoffice,
long-context and compaction; retrieval retains the decimal precision:

| Derived task | Measured source task | Source time (s) | Published par (s) |
| --- | --- | --- | --- |
| `bo-reconcile` | `bo-pnl-runway` | 27.5 | 55 |
| `ir-server-logs` | `ir-studio-wiki` | 14.6 | 29.2 |

These pars are reference times for scoring, not a duration estimate for any agent.

## Multi-step tasks

`cmp-*` tasks have two steps. The second runs with `fresh_session` (a new agent
process, no chat history) and `carry` naming the summary file: the runner
builds a new workspace that contains only that file (plus AGENTS.md), under
a separate system-temp root, so neither the source nor any copy of it, nor
the step-1 workspace, is inside or above the step-2 directory. `hide` also
names the source for the record. What remains unenforced: an agent that
ignores AGENTS.md could still open an absolute path elsewhere on the disk;
only an OS sandbox around the agent closes that (docs/SCORING.md).
