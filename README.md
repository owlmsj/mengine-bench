# mengine-bench

**How well does your coding agent do real work, and how fast?** 15 everyday jobs,
one Score, about 15 minutes for a good setup. Every result is public and auditable.

It grades the whole **agent**: the harness (Claude Code, Codex CLI, opencode, AGY or your
own command) + the model + its effort + your hardware + your configuration. Change
any of them and you have a different agent. It is an educational benchmark, not an
official one: use it to learn how your setup behaves and to compare it with others.

Results: [LEADERBOARD.md](LEADERBOARD.md).

## How a run is graded

**Score = 0.6 x Correct % + 0.25 x Judge + 0.15 x Speed x Correct % / 100.** Speed pays only for work that is right.

| | The question | How it is measured |
| --- | --- | --- |
| **Correct** | Did it do the job? | Deterministic checks on what was delivered: hidden tests, numbers within tolerance, file state. Anyone can reproduce them. |
| **Judge** | Is the work good? | One LLM vote per task (Claude Opus 5.5, xhigh), with subscores, blind to the model and the speed. |
| **Speed** | Was it quick? | 100 at 5 min of total agent time or less, 0 at 30 min or more, linear in between. |

Example, from the leaderboard: Correct 100, Judge 84.1 and 21 min 44 s (Speed 33.0)
give 0.6 x 100 + 0.25 x 84.1 + 0.15 x 33.0 x 100 / 100 = **86.0**. It solved all 14 tasks, and
thinking time cost it about 10 points. Cost and an estimated price at API list prices are shown too, but never count.

Formulas and edge cases: [docs/SCORING.md](docs/SCORING.md).

## The 15 tasks

Each runs in a fresh folder, needs no web and has a limit of 3 to 7 minutes. If time
runs out, what is in the folder and the reply so far still get graded, and the prompt
says so. Each task has a reference solution that the test suite proves passes.

## Run it

You need [uv](https://docs.astral.sh/uv/), the agent CLI you want to measure, logged
in, and [gh](https://cli.github.com) to submit.

```
git clone https://github.com/owlmsj/mengine-bench.git
cd mengine-bench
uv sync
uv run mengine-bench run --agent claude --model claude-sonnet-5-5 --effort high --dry-run
uv run mengine-bench run --agent claude --model claude-sonnet-5-5 --effort high
```

The dry run prints the plan and runs nothing. The real run takes about 56 minutes at
worst, with every limit hit, and ends with `privacy check: clean`. Read
`results/<run>/summary.md`, whose "Failed checks" say what each check expected and received, then publish it with
`uv run mengine-bench submit results/<run>`. Grading the three pages needs a Chromium-family browser (Edge, Chrome or
Chromium); without one, their page checks are left out and the run says so.

| Harness | `--agent` | `--model` example | Cost |
| --- | --- | --- | --- |
| Claude Code | `claude` | `claude-sonnet-5-5` | reported by the harness |
| Codex CLI | `codex` | `gpt-6.1-sol` | `--price input=X,cached=Y,output=Z` (USD per 1M tokens) |
| opencode | `opencode` | `provider/model` | reported by the harness |
| AGY | `agy` | `gemini-4-argon`, with `--effort high` | not reported |
| anything else | `cmd` | any label | `--cmd "my-agent --prompt-file {prompt_file}"` |

Two tips for a fair run:

- **Local model?** Load it first, since a cold load counts against the first task. Use `--price 0`.
- **Describe your setup** with `--config key=value`, for example `--config quant=Q4_K_M --config ctx=256k`. It is recorded, never applied.

### Or let your agent do it

Paste this into a new session of the agent you want to measure:

````text
Benchmark yourself with mengine-bench (https://github.com/owlmsj/mengine-bench).
1. Find your harness (claude, codex, opencode or agy), the exact model id that CLI
   accepts and your effort.
2. Clone the repo if needed, cd into it, run `uv sync`.
3. Run `uv run mengine-bench run --agent <harness> --model <model> [--effort
   <effort>] --dry-run` and show me the output. Wait for my "go".
4. Run it again without --dry-run, in the background or without a timeout, and
   wait until it ends with "privacy check: clean". Do not help the agent under
   test or touch its files.
5. Show me results/<run>/summary.md. Submit only when I say so, with
   `uv run mengine-bench submit results/<run>`, and reply with the PR URL.
Report only values copied from command output. Never print credentials.
````

## The rules

- **Evals are open briefs.** Each states the context, the problem and the outcome wanted. How to get there is the agent's call; the result in `result.json` and the files it delivers are what get checked, never the chat.
- **Everything its harness gives it** is allowed: shell, web, browsers, MCP servers, skills, subagents. Every step's prompt says so. Reading the reference, the hidden tests or a published answer is not: the run gets rejected.
- **Personal instructions count as configuration.** `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.gemini/GEMINI.md` and any `CLAUDE.md` or `AGENTS.md` above the temp dir are recorded by name and shown on the leaderboard. Move them aside for a plain run.
- **Memory across sessions is off inside the bench, on Codex and Claude** (`--disable memories`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY`). Daily use keeps it on. It carries earlier runs into this one, the same leak as an earlier workspace left on disk.
- **Rankings compare the same bench version.** Older rankings stay on the leaderboard as history, with the Scores of their own formula.

## Privacy

Transcripts are published. Before writing the bundle, the bench replaces secret-looking
values, e-mail addresses, home and run paths, your user, host and git names, and the
names of your account's connectors. It cannot know your company, clients or private
projects, so skim `results/<run>/` before you submit.

## Limits

- One run is one sample, and runs are not repeated. A lead that holds in under 80% of the draws of the tasks is a tie, and that says nothing about the noise between two runs of one agent.
- Results are self-reported. The transcripts let anyone check a run, but nothing re-runs it.
- The task folder is an instruction, not a sandbox: an agent with full permissions can read the rest of your disk.
- A timeout or a crash with nothing written has nothing to grade. There are no retries.
- Time depends on your machine and network, and Cost is an estimate.

## Develop

```
uv run pytest -q                   # gold self-tests, no model calls
uv run mengine-bench selftest      # every task's reference solution
uv run mengine-bench list
uv run mengine-bench analyze       # what separates the published runs; no agent runs
uv run mengine-bench judge-anchors # after a rubric change: four judge votes
```
